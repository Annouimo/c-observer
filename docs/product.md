# 产品定位与 MVP

状态：初始设计，待共同评审。

## 定位
C Observer 是 C 语言课程学习、作业和考试场景的只读运行观察器，而不是通用调试器或 IDE。主要对象是几十至几百行的单文件 C99 程序，预先给定的 stdin，小规模查错样例，短生命周期、可复现运行。学生关注下标、循环、条件、数据更新、排序比较、递归，而非线程、系统调用、复杂工程构建。小样例不意味着数组声明容量一定小，也不保证程序一定终止。

目标：在不学习 GDB 指令的情况下，从源代码位置和变量变化发现程序行为与预期的差异。离线、确定性、不生成解题代码；考试使用以课程规定为准。独立使用，也可由 Accoding Companion 传入源码及样例。

## 默认流程
选择 C 源文件和输入（可选预期输出）→ 自动发现工具链、编译、采集 → 逐步展示已有快照 → 自由回放 → 在外部编辑器修改代码 → 重新运行。Companion 入口跳过手动选择。默认采集历史；是否需要实时单步由真实性能和兼容性测试决定，不预先承诺全程采集。

## MVP
- 单屏：少量执行上下文、全宽数据区及回放进度；完整源码、调用栈、输入输出按需查看。详见 [design.md](design.md)。
- 自动采集、渐进浏览；前后跳转、首尾、执行起点及相邻历史快照的可靠变化；无法确定单行归因时明确标为区间变化。
- 基本类型、字符串、一维数组、结构体、结构体数组；未采集部分明确标示。
- 支持停止、异常保留历史、采集上限提示、重新运行。错误和正常退出可区分。
- 默认避开库和已知辅助实现；必须尽可能保留用户回调（如 qsort 比较函数）。后端不能可靠做到时明确说明，不伪造完整性。
- 只使用现有真实工具链；不强制要求用户改 PATH。工具链缺失给可操作提示。

后续：按变量/代码行索引、调用栈切换、矩阵、自动播放、实时单步（如果需要）、全局/静态变量扩展。
非目标：编辑器、项目管理、任意进程附加、远程/多线程调试、汇编/寄存器、任意内存浏览、修改变量、真正逆向执行、AI 解题、自动修复算法。

## 成功标准
用学生真实题型评估是否比 printf 更省事；小样例下启动、采集、回放顺畅；Windows 课程工具链可用，不能牺牲 Companion 普通评测稳定性。不能用“实现了多少调试功能”衡量成功。

# 里程碑与验收

## 0：共同接口
当前阶段：共享 Go 模型、流式事件草案、产品与 UI 规范、合成快照。Codex 审核真实调试器实验数据、可取得的作用域身份、数组/结构体类型、输出边界、进程生命周期和采集性能。双方确认后建立 feat/engine 和 feat/tui；不抢先冻结接口。

## 1：并行实现
Engine: GDB/MI 与 LLDB/DAP、工具链检测、编译与捕获、有限快照、取消、实际跨平台测试。优先 Windows 旧 MinGW。
TUI: 使用合成快照及假 Engine 运行，单屏回放、变量树、数组/结构体、源码高亮、输入输出、限制提示与重跑。第一版只做 P0。
共同：编译错误、正常/异常退出、达到上限、同名变量与作用域、不可取得值、大数组、有无预期输出。

## 2：真实集成
真实程序验收：数组求和、冒泡排序、二分查找、生日结构体查询（故意误用下标）、qsort 布尔比较函数、字符串统计、递归阶乘、多组数据、除零/异常、无限循环。测量实际采集延迟、快照数、内存占用；报告中区分平台真机运行与交叉构建。不得假定任意越界都会触发异常。用户确认 UI 后再发行。
## 3：分发和 Companion
单 Go 二进制；复用已有工具链，按需求评估打包调试器。独立 CLI 输入、与 Companion 终端移交、#line 原始源码映射；正式提交不保留工具生成的 #line。Companion 仅调用观察器，不依赖其内部实现。集成需另行批准。

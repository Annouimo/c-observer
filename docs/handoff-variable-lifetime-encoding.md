# Codex 交接：变量身份可靠性与紧凑编码实测

## 目标、基线和边界

承接 PR #12 及 [research/identity-output 研究报告](https://github.com/Routilet/c-observer/blob/d1b14382d0401d4ba6c643eecaf345fc00840817/docs/identity-output-research.md)。该分支已有入口 main 最外层变量 AST 回退及大 AST 解析修复；代表性生日夹具通过 Linux GDB/LLDB、Apple Silicon Xcode LLDB 验证，但原始课程程序仍待复测。循环控制变量、循环体局部和普通函数调用实例尚不可靠。

本轮分两个独立问题：A. 可靠识别更多变量；B. 降低身份编码的时间与空间成本。编码不得改变身份判定。优先课程常见场景和低维护成本；不要求完备的 C 生命周期跟踪。先实测并交报告、最小实验及接口建议，不擅自改正式共享接口或发行版本。

阅读 AGENTS.md、docs/interface.md、docs/design.md、docs/record-format.md、上述报告及引擎代码。以已经实测的 research/identity-output 提交 d1b14382 为实验依赖，另建短分支，说明与 main 的关系。将前轮可独立交付的修复整理为正式后端 PR，不让本轮探索阻塞该修复。保留并行前端 PR #13。输入进度与 stdout 缓冲预研已经结束，不重新开启。

## A. 可靠身份识别

### A1. 分离证据

- 声明身份：同一编译单元、源码声明位置及词法作用域，不是同名变量。
- 动态身份：同一次函数调用、同一次对象生命周期。静态存储单独处理；成员由父对象和成员键确定。
- 值证据：调试器可读且显示值完整，不等于 C 语义上已经初始化；不把读取到的零值当成初始化或赋值证据。

现有 IdentityReliable 仍表示动态身份可靠，可靠 ID 在单次运行内不复用。不能仅用声明 ID 或地址替换动态 ID 来提高覆盖率。相邻暂停点差异不是完整赋值日志，也不保证单行归因。

### A2. 词法作用域（P0）

LLDB：扩展现有一次性 Clang AST 索引，试验记录用户函数、参数、CompoundStmt、ForStmt 等作用域和声明范围；优先调试器声明证据，缺失时才保守回退。结合冻结实际源码、SourceMap、#line、文件/列/字节位置，处理同一行多声明、同名遮蔽及宏。候选不唯一则降级。不在每次暂停重复解析 AST。

GDB：复用 Python 的 frame.block、Block 层级与 Symbol 声明，实际测量嵌套块信息及旧条件 block.function 非空的覆盖限制。不为 GDB 强制依赖 Clang。

### A3. 动态作用域（P0）

先支持普通结构化 for 控制变量，再评估循环体和嵌套块：

    for (int i = 0; i < 3; ++i) {
        int x = i * 2;
        ++x;
    }

同一次 for 执行中的 i 是同一对象；每次重新进入循环体的 x 是新实例，外层循环重新进入内层 for 时也可能创建新控制变量。词法声明相同不意味着对象实例相同。非 VLA 自动对象的存储生命周期、声明可见性和初始化时点不得混同。

研究现有 next/step、显式断点和跳过辅助函数的执行证据，按可证实的进入/退出边界分配实例。两端处于同一词法范围、相同地址/PC/调试器引用均不足以证明中间未退出重入。缺失快照或不完整枚举不证明退出。对无法证明连续的区间断开比较链；不要求覆盖 goto、宏、多控制结构同一行、回调及不可映射位置。若需要明显增加请求或停靠次数，先报告，不引入完整控制流分析、逐指令追踪或用户源码插桩。

### A4. 函数调用实例（P1）

实测两套调试器现成只读帧信息、栈位置、调用者链及返回地址能否建立调用实例。不要假定 GDB 内部 frame ID 直接暴露给 Python，或 DAP frameId 跨暂停稳定。地址和调用点可能复用；同一栈深、同一函数、相同栈后缀均不足以证明连续。验证连续调用、递归进入与返回、qsort 回调、静态变量跨递归共享。无法确认边界继续降级。

### A5. 初始化与分级表达（仅接口候选）

实测初始化前暴露的值、声明行暂停、同一行多个声明、无初始化/条件赋值及循环体重入。不做通用 definite-assignment 分析。可确认初始化时才报告初始化事件；否则仅称观测值。

评估低成本独立声明证据、调用实例证据、动态生命周期证据的可得性：
- 同一可靠对象的完整可比较观测值差异：现有可靠变化。
- 确认新实例：展示当前值及新实例，不与旧实例作赋值比较。
- 同一可靠声明且同一可靠调用实例，但动态作用域连续性未知：候选「观察值差异」，不进入可靠变化筛选或统计。
- 证据不足：仅展示实际采集值。

以上是待评审产品语义，不能直接改变 IdentityReliable。提出最小可选字段、证据来源、缺失语义和旧记录兼容方案。旧记录不回填可靠性。

### A6. 正反例与实机验收

每类用例既检查应该匹配的相邻节点，也检查绝不能匹配的实例。用独立人工标注的预期对象关系和真实暂停记录判断，不以新算法输出自证正确；不要为测试误把调试器可读的未初始化值认作有效旧值。

| 场景 | 重点 |
| --- | --- |
| 普通 for、同一 for 多轮 | i 连续变化可识别 |
| 三个相邻 for 同名 i | 不混合不同声明 |
| 循环体 x、index、y/m/d | 同轮可比较，重入不得复用实例 |
| 外层循环重新进入内层 for | 不复用内层动态身份 |
| 同名遮蔽、同一行声明、break/continue/goto | 不误匹配，复杂场景允许降级 |
| 多次普通函数调用、递归、qsort | 同调用内比较，不跨调用混淆 |
| 全局/静态、结构体、数组页、VLA | 保持已有可靠行为，未采集不推断 |
| 完整 preset 装配及真实生日题 | n/q/birthdays 既有修复保留；争取循环变量覆盖 |
| 空历史、超时、取消、不可映射/不完整快照 | 不制造身份事件 |

Linux GCC/GDB 与 Clang/LLDB 优先，Mac Xcode LLDB 和 Windows MinGW GDB 原生验证（若环境不可用提供可重复验证包，由维护者执行）。区分实机、模拟缺失协议字段、合成夹具和交叉构建。

## B. 标识符编码及成本实测

### B1. 先测基线，不预设瓶颈

当前 Frame.ID / Variable.ID 是 string；可靠成员 ID 如 entry-main:11:birthdays/[2]/.date/.day 重复出现。现有 TUI 用 map[string] 匹配相邻对象，并非全量两两逐字比较；Go map 会哈希并验证键相等。LLDB 引擎按每份快照 JSON 编码长度累计 MaxHistoryBytes（默认 32 MiB），这是历史编码预算，不等于真实堆内存；核实 GDB 对应路径。大 AST 的 30 MB 是独立问题，不算进 ID 字节开销。

用同一份真实记录（上一轮脱敏 birthday-native/expanded/gdb 等、维护者允许的本地原始记录）及大型数组、结构体、多标量、循环重入、递归、接近上限的长历史测量：
- 帧/变量 ID 出现次数、唯一键数量、平均/最大长度、可靠/不可靠分布、重复率。分别统计全量原始字符串 UTF-8 字节、实际 JSON 中 ID 字段（转义/字段开销独立）、完整记录和每快照字节。
- 采集阶段 ID 生成、拼接、哈希/查表、序列化预算开销；通过基准测试、allocs/op、B/op、CPU/heap profile 与必要时峰值 RSS 评估，区分累计分配与保留内存。不能仅用 len(string) 推算 Go 堆内存。
- 前端相邻匹配/历史索引的代表性成本可用独立实验模拟或既有只读基准；不修改 internal/tui。单独测纯编码/匹配与真实完整采集，避免把调试器耗时归给 ID。
- 记录真实触发的预算上限、快照数量与结束原因。若原程序不足以达到上限，单独标识重复/合成压力数据，不称实测采集。

### B2. 比较编码路线（使用完全相同的已判定身份）

1. 当前长字符串（基线）。
2. 64 位及可选 128 位 Hash（选标准库或无新增依赖的算法；明确字节序、格式、碰撞模型）。固定长度并不意味着可直接证明同一对象。纯 Hash 只能作为性能/体积实验，不允许进入可靠比较。若使用 Hash 索引必须有精确原键比对及碰撞分辨策略，计入额外存储。
3. 优先：每次运行的字符串驻留/字典，例如 map[string]uint32，精确键相等才复用编号，单调分配、不复用、0 保留为无有效身份；验证上溢行为。分别试验 (a) 保持现有 string 字段、驻留共享底层字符串或使用短数字文本；(b) 实验用 uint32 ID 加一次性字典。不要将相同临时 ID 跨生命周期变为可靠 ID，保留不可靠值的展示定位及原可信度。
4. 若收益明显再评估结构化键：DeclarationID、FrameInstanceID、LifetimeID；成员以父对象 ID + 带类型的成员键（数组实际下标/字段声明等）驻留，避免重复构造长路径。静态对象另行建键。帧/对象/声明的命名空间显式区分。
5. 仅导出压缩作为对照（gzip 或字典编码），区分减少磁盘体积与运行期内存/预算收益。现有记录 v1 保持可读；本轮实验不更改正式记录格式。

固定比较语料，验证映射前后身份等价关系、可信度、原始值、成员关系及变化结果完全一致。Hash 碰撞可用故意退化的测试 hash 强制构造，验证不同键不会被合并。包含同名变量、不同调用实例、重新进入作用域、可靠/不可靠 ID 相同文本、不同运行、字典缺项/重复/溢出及终止清理。编号在单次运行内稳定即可，不要求跨运行相同。

### B3. 实测指标及结论

输出每种方案的实际数字而不是理论比例：完整 JSON 字节及压缩后字节、字典/索引额外字节、保留堆/分配量、身份生成与查找 ns/op、回放比较耗时、整个观察耗时及实际预算下保存快照数。uint32 二进制占 4 字节不代表 JSON 数字固定 4 字节；计入字典、map、对象对齐和转码成本。

至少重复三次同条件完整运行并记录环境、Go/编译器/调试器版本；微基准用 go test -bench -benchmem -count=5 或相当方式，列中位数和波动范围。相同快照数量才能直接比较耗时；提前到达上限的运行单独报告。保持原 1000 快照、10 秒运行、2 秒请求及 32 MiB 历史预算作为默认对照，不为了改善结果擅自放宽预算。实验内部可以设置另一组等条件压力上限并明确标注。

判断哪层值得优化：单纯导出压缩、内存字符串驻留、短 ID 或共享模型改造；如果真实收益小，保留现状。优先最低复杂度方案，不为节省少量空间引入新依赖或复杂二进制协议。若建议紧凑记录，提出格式版本、v1 向后读取、字典边界检查、导出可诊断性、预算如何统计及迁移步骤，先评审。

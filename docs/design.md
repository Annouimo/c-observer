# Observer 设计规范

Observer 是面向 C 语言课程的离线、只读运行观察器。减少学生的界面管理成本，而非重建 IDE 或通用调试器。

## 核心原则

1. **执行对应。** 高亮刚执行的源码，展示执行后的数据状态及与执行前相比的可靠变化。同一回放步的语义不随导航方向改变。不能确定单行归因时，明确标为采集区间变化；不把停靠行误作已执行行。
2. **数据优先。** 主界面只保留少量执行上下文、变化摘要、进度和必要操作提示；数据使用全宽剩余空间。完整源码、调用栈、输入输出按需查看，不常驻分栏。
3. **全局布局。** 同时考虑终端宽高，先为全部观察对象分配最低可读空间，再优先完整展示小对象并扩充大型对象预览。
4. **默认可见。** 默认观察当前帧及已记录全局/静态数据。尽量保证所有顶层对象的首屏概貌；先横向排列和紧凑表达，再缩减预览，最后才整体滚动。禁止以声明容量作为隐藏对象的理由。
5. **稳定回放。** 同一观察阶段的对象顺序、位置、列宽及预览范围尽量固定；普通数值变化不触发重新布局。变化标记仅表示该步的原始相邻快照差异。
6. **按需深入。** 主界面负责整体观察，详情负责完整已采集内容并支持继续回放；不要求用户管理面板。渲染形式依据真实字符宽度与内容选择（行式、索引列表、表格、嵌套分组），自动提供完整、紧凑、概览候选。
7. **忠实呈现。** 仅比较身份可靠且可比较的值；区分未展示、未采集、无法读取及截断。不得推断初始化、实际访问、逻辑长度或伪造结束快照；完整原值可查。

## 验收

- 执行位置与前后状态对应；覆盖首帧、循环、调用/返回、递归、不可映射位置、结束及跳转。
- 80×24、120×30、160×40 终端下测首屏对象覆盖率、已记录数据展示完整度、布局稳定性及字符宽度。
- 重点案例：C6-D 多矩阵、E4-E 长整数、E4-G 嵌套数组、E6-E 递归与矩阵、E6-D 稀疏下标、E2.5-D 多标量和大数组；保留其他典型案例。
- 合成夹具、CI 构建、真实 GDB/LLDB 运行、原生终端视觉验收分别记录，不互相替代。

现有 Engine.Run / RunResult 接口保持不变；底层快照仍表示暂停位置。实施细节见 docs/frontend-next.md；共享契约见 docs/interface.md。

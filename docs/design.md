# Observer 设计规范

Observer 是面向 C 语言课程的离线、只读运行观察器。帮助学生看清程序怎样改变数据，不重建 IDE 或通用调试器。

## 核心原则（按优先级）

1. **执行对应。** 以较早暂停点表示观察区间的执行上下文，以较晚快照展示数据状态。源码、变化、状态、输入输出对应同一时间线。变化始终来自相邻原始快照，不随导航方向改变；目前允许区间归因，不能假称精确单行归因。首帧是观察起点，结束页不是快照。
2. **数据真实性。** 相邻快照优先按可靠身份比较；身份不足时，以兼容函数/调用层、唯一名称、类型、成员路径及真实下标建立观察值对应，已知声明或可靠 ID 冲突不比较。仅比较已读取、未截断的值；不将候选对应称为同一对象赋值。长期对象历史及自动聚焦仍使用严格身份。区别已知不变、无法比较、新进入作用域、首次采集、退出作用域及数值改变；不能推断初始化、实际访问、逻辑数组长度或未采集值。区分未展示、未采集、无法读取与截断。
3. **变化突出。** 执行区提供简明前后值差异，数据区原位高亮。大量变化使用数量摘要，详情可查看全量已记录变化。变量变化检测是核心正确性问题，不因单行归因尚未解决而降级。
4. **信息精简。** 默认只展示理解当前执行所必需的信息。技术限制在相关对象上紧凑表达，完整解释按需查阅；不可因简洁隐瞒不确定性。颜色有明确语义：蓝色执行/焦点、绿色可见数值差异、灰色辅助信息、红色异常；关键状态不能仅靠颜色。
5. **数据优先。** 上方为紧凑的执行上下文与变化（左）、输入输出（右），共享有限高度；下方为全宽数据，底部进度与常用操作。小终端可退化为紧凑纵排。输入和本次运行的最终输出是核心信息，不再默认隐藏；当前步骤的已捕获输出在详情访问。完整源码、调用栈、预期输出按需展开。
6. **全局布局。** 同时考虑终端宽高，先给所有顶层对象最低可读概览。集中排列标量、短字符串等紧凑对象，大对象占剩余空间；优先变化、选择对象及相关上下文。完整/紧凑/概览候选按真实字符宽度选择。不以声明容量为隐藏理由，不为填满界面重复低信息量数据。允许留白。
7. **稳定回放。** 同一观察阶段的对象顺序、位置、列宽和预览范围尽量固定，必要时移动窗口以显示可靠变化；不因普通数值变化或导航方向而重排。默认观察当前帧与已采集全局/静态数据，不混淆不同递归帧。
8. **按需展开。** 详情提供完整已采集内容并支持继续回放。连续且确实相同的完整未截断元素可无损折叠。对于部分采集对象，允许仅折叠连续、已观察且未截断的相同预览字段，以 ≈ 明示预览相同而非整个对象相等；变化项及含可靠变化子项的预览不得折叠，不把缺采当重复。矩阵保留空间结构。保留类型化渲染（行式、索引列表、矩阵、表格、嵌套分组）。常用键位常驻，低频操作统一入口，用户不必管理面板。

前两条是正确性约束，不能为了体验优化而破坏。主界面不重复提示身份等级、自动关注范围或采集统计；未读取和省略内容仍如实表示。

**适度实现。** 优先解决真实课程使用中频繁出现、显著妨碍查错的问题，兼顾实现成本与长期维护成本。低频或无法低成本可靠支持的场景允许明确降级；不追求通用调试器的完备性。先集成可验证的最小有效改进并恢复实际使用，再由具体反馈决定下一轮。

## 当前实施范围

0.1.1 已提供记录导出及离线回放。0.1.2 集成 #15 主要变量身份修复和 #13 紧凑界面；通过现有 CI、代表性生日题真实回归及维护者实机使用验收后发行。只修复阻断问题。循环和复杂调用身份、分级变化、进一步布局算法及编码优化按使用反馈评估，不是本轮发行要求。输入进度、stdout 缓冲研究已结束，维持原始行为。详见 [roadmap.md](roadmap.md) 和 [research-index.md](research-index.md)。

## 验收

- 执行位置与前后状态对应；覆盖首帧、循环、调用/返回、递归、不可映射位置、结束及跳转。前进、后退、跳转至相同位置的可靠变化一致。
- 80×24、120×30、160×40 原生终端下测首屏对象覆盖、有效信息密度、变化显著性、布局稳定性、字符宽度及键位。CI 全绿、合成夹具和真实终端视觉审核不可互相替代。
- 保留典型压力案例：C6-D 多矩阵、E4-E 长整数、E4-G 嵌套数组、E6-E 递归与矩阵、E6-D 稀疏下标、E2.5-D 多标量和大数组。本轮重点验证生日题及少量真实代表性课程案例，其他题型按反馈补充。使用实际用户程序及样例，不将构造记录冒充实测。
- 记录导入导出需验证原始数据及每一步回放一致、无工具链运行、未知格式/损坏记录、空历史及不完整运行、隐私提示。区分实际测试与尚未实测平台。

现有 Engine.Run / RunResult 不变；底层快照仍表示暂停位置。记录外层封装由 TUI 持有，不改变后端与 Companion 会话协议。共享契约见 docs/interface.md；后续改动按 AGENTS.md 协调。

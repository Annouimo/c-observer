# 前后端接口草案

状态：待双方确认。Go 类型定义在 `internal/observer/model.go`。JSON 用于测试和调试。

## 运行一次，返回一份记录

`Engine.Run(ctx, LaunchConfig) RunResult` 是阻塞调用。TUI 在后台调用，等待期间显示运行状态，并允许停止。调用返回后，TUI 一次拿到源码快照、全部已完成的观察快照、诊断、输出和结束原因，再进入回放。重新运行创建新记录。此草案的运行与回放约定适用于产品和 TUI 草案中提到的渐进浏览流程。

停止由调用方取消 context。引擎停止发起采集请求，先尝试让调试器终止被观察程序，再按平台做有界清理，等待本次启动的可管理进程退出。清理使用独立的短期限。清理失败填入 `CleanupError`，保留原结束原因和已采集数据。引擎的退出不依赖 TUI。

每次调用都有一个结果。参数错误、编译失败和工具链初始化失败可返回空历史。正常退出、非零退出、信号或异常、运行超时、请求超时、主动取消和采集上限各自有结束原因。只有拿到真实退出码时才填 `ExitCode`。正常退出只说明程序退出。达到上限时在 `Message` 说明具体限制。已有的完整快照从 0 开始连续编号，按采集顺序返回。TUI 将结果视为只读。

## 输入、源码和显式停靠

`LaunchConfig` 包含编译入口、工作目录、预设 stdin、可选预期输出、工具链覆盖、编译参数和采集限制。预期输出只用于展示和对照。路径相对给定工作目录解析，用户参数不拼成 shell 命令。采集构建与正常评测分开，保留相对 include 的解析环境。

每次运行冻结可见源码。引擎须保证返回给 TUI 的源码与实际观察版本一致。若无法保证，应报告失败或将该文件标为不可映射。 `SourceMap` 从调试器报告的逻辑路径映射到可见源码路径，用于 `#line` 等装配场景。 `SourceLocation.File` 对应本次 `SourceFile.Path`。未映射时留空，可用 `ReportedFile` 保留调试器原路径。调试器未提供行号时 `Line` 为 0。无可见源码的位置仍可保留快照。位置表示当前暂停点，后续才从这里继续。

默认步过库和已知辅助函数。调用方可在 `KeepLocations` 指定用户源码停靠点，绑定成功后优先于跳过规则。绑定失败给出诊断。 `ExplicitStops` 表示后端支持此能力，不能据此推断回调均已采集。Linux 上实测 GDB 和 LLDB 普通步过会越过 `qsort` 的用户比较函数，给比较函数设置已绑定的断点后，两者都能停住。

## 变量和数组

- 帧按栈顶到栈底排列。可靠的帧和对象 ID 只在本次运行内有效，且不复用。函数名、深度、显示名称与调试器临时引用都不足以单独构成可靠 ID。身份存疑时由帧或变量的 `IdentityReliable` 降级。只有两端都可确认是同一对象且值可比较时，才显示变化。
- `Scope` 尽量区分参数、局部、文件静态、函数静态与全局。后端无法判断时留空。 `Declaration` 可选。能确认时，多个递归帧引用的同一个函数静态对象共享对象身份。帧的 `VariablesComplete` 和快照的 `GlobalsComplete` 标记是否完整枚举对应对象，值本身仍可未采集。列表不完整时，缺失项的作用域状态未知。
- `Value` 是显示文本。 `observed` 表示调试器可读。未采集是 `not_captured`，读取失败是 `unavailable`。 `ChildrenComplete` 只描述直接子节点。字符串截断用 `ValueTruncated`，数组容量用 `ArrayLength`，数组元素用真实下标。没有记录的历史值显示“未记录”。
- 数组默认采集前缀。重跑可用 `ArrayRanges` 为指定对象替换默认页。 `Path` 只允许变量名、点分成员和字面量非负下标，比如 `birthdays` 或 `rows[8].scores`。可用声明位置消除同名歧义。 `Start` 从 0 开始，`Count` 必须为正，受每数组上限约束。目标不唯一时报告诊断，数组末尾按实际容量截短。回看历史时不补采。

GDB/MI 实测能返回同一帧中的两个同名值，按名字求值只得到内层对象。LLDB/DAP 在夹具里还提供了声明位置。两套后端都验证了递归帧中的不同值，跨暂停身份仍需引擎单独验证。

## 输出和预算

`RunResult.Output` 分别保存 stdout 与 stderr 的有界原始字节前缀，明确标记截断。每条快照只记当时已经捕获的两路字节数，回放时从最终前缀取对应长度。偏移从 0 开始、不递减，且不超过最终保存的字节数。缓冲和异步读取会影响观察时点，界面不据此把输出归因到某行。输入显示原始样例，首版不跟踪消费位置。终端控制字符由前端转义。

初始建议为 1,000 个快照、10 秒运行预算、单请求 2 秒、每数组 16 个元素、树深度 4、单快照 512 个节点、每路输出 64 KiB、历史 32 MiB。限制为 0 时使用默认值，负值视为参数错误。运行预算从调用开始计时，清理另有短期限。输出截断后继续排空输出，避免写入端被堵住。节点或深度预算耗尽时保留可用部分，标明不完整。快照或历史预算用尽则结束采集并保留已有快照。

Linux 预研中，连续采集 1,000 次摘要，GDB 约 0.56 秒，LLDB 约 1.74 秒。GDB 对 4,096 元素数组完整读取 1,000 次约 9.22 秒，限量读取约 1.07 秒。默认值还需用真实 Go 引擎和 Mac 真机测首屏等待、数组页开销和清理时间。平台优先级为 Mac、现代 GCC/GDB、按需验证旧 MinGW。

## 同步和验收

接口变更同步更新本文件、模型和合成夹具。至少检查正常、空历史、取消后保留历史、采集上限、输出偏移和部分数组。身份、显式停靠、特殊路径以及进程清理另用真实调试器测试。双方确认本草案后，再从共同提交建立前端和引擎分支。

# Codex 交接：标准输入读取进度采集预研

## 目标与边界

维护者希望 C Observer 的主界面在源码右侧紧凑显示输入与输出，并随历史回放移动到实际读取位置。此次只验证**输入后端**：能否在现有 GDB/LLDB 采集架构下，以轻量、可靠、跨平台的方式取得 stdin 消费进度。先提交实验及报告，不直接改变正式接口或默认运行行为。

阅读 AGENTS.md、docs/interface.md、internal/observer/model.go、internal/engine/engine.go、internal/engine/gdb.go、internal/engine/gdb_capture.py。以 main 最新代码为基线，保留其他未合并工作。

现状：stdin 由 LaunchConfig.Stdin 写入临时文件并重定向给被观察程序；每个 Snapshot 已有 OutputOffsets，但没有输入偏移字段。Engine.Run 是阻塞采集，前端离线回放。不要将文件描述符读取进度、源码行号、scanf 调用次数或变量值猜测为实际消费位置。

## 1. 首选验证路线

- 在真实被观察进程的安全暂停点，试验通过调试器取得 C stdio 的逻辑位置（例如 ftell(stdin)，必要时比较 ftello 或平台对应 API）。先验证能否执行、表达式兼容性、返回值、耗时和副作用。GDB/MI、LLDB/DAP 应按各自实际能力分别测试。
- 将 OS 文件描述符/句柄位置作为对照而不是正式方案：stdio 可能一次预读整个文件，但程序只消费少数字符。
- 特别验证 Windows CRT 文本模式 LF/CRLF 转换、位置值是否为原始样例的字节偏移。ftell 在文本模式可能是不可直接解释的位置标记；不能仅因其单调增长就认定可映射。fgetpos 的结果也不是天然字节偏移。
- 若调用 inferior 函数会改变状态、产生额外停靠/信号、破坏调试器步进、可能阻塞或超时，则记录限制，不能强行启用。比较调用前后 stdout、stderr、退出码、EOF/错误状态、后续读取结果及源代码停靠序列。不得通过 fflush(stdin)、fseek、setvbuf、强制二进制模式或重写用户 scanf 实现来掩盖问题。
- 若首选方案不成立，可短时间评估调试器只读检查 CRT 缓冲状态或其他现成机制的可行性；注明平台、CRT 和版本依赖。不要引入重量级解析器、全套 stdio 包装、系统调用跟踪框架或长期维护负担。允许个别平台或场景降级。

## 2. 实验用例

先用 ASCII/LF 输入固定字节串 `12 34\nabc\nX\n`（这里的反斜杠 n 表示换行，实际文件必须按给定字节生成，不由编辑器转换）。用一个小 C 夹具，逐行执行 scanf("%d",&a)、scanf("%d",&b)、getchar()、fgets(buf,sizeof buf,stdin)、getchar()、ungetc(ch,stdin)、getchar()、getchar()、再次 getchar()。让每次调用后都有用户源码停靠点，并核对实际返回值，防止调试器略过。

| 操作完成后 | 预期逻辑位置（LF 原始字节边界，从 0 开始） |
|---|---:|
| 初始 | 0 |
| scanf 读 12 | 2 |
| scanf 读 34 | 5 |
| getchar 读换行 | 6 |
| fgets 读 abc 和换行 | 10 |
| getchar 读 X | 11 |
| ungetc 把 X 放回 | 10 |
| getchar 再读 X | 11 |
| getchar 读换行 | 12 |
| getchar 返回 EOF | 12 |

EOF 必须区分“当前位置到末尾”和“读取已返回 EOF”；不从偏移推断 feof。对于无法准确映射的场景，应输出未知状态而非近似值。

追加代表性夹具：

- 一行多个整数、跨行 scanf、前导/连续空白、空行、%c 与前导空格、%s、匹配失败（返回 0）、EOF、空输入、末尾没有换行。
- fgets 部分读取长行、逐字符 getchar、ungetc（包括不同字符放回；此时偏移不一定描述流的完整内容），fread；如果不支持，明确降级。
- fseek/rewind/freopen、非 stdin 输入流等边界，不能误报为常规顺序读取。验证回退位置不能强制单调。
- LF 与 CRLF、混合换行、UTF-8 多字节（按字节而非字符索引；前端以后负责安全显示）。
- 真实课程用法：B 生日题（read_word、read_int 混用；可用维护者的 main.c、原始样例与实际展开的 preset）；D 不定行直到 EOF；Y 一行大量数字逐个读取。优先覆盖普通 scanf/getchar/fgets，不依赖 C Exam Kit 专用接口。
- 正常退出、崩溃、取消、采集上限、重跑；输入位置读取失败不能抹掉已有有效快照或阻止普通观察。不要补造结束快照。

## 3. 跨平台及性能

至少验证 macOS Clang/LLDB（实际 DAP）、Linux GCC/GDB（MI + Python）、Windows x64 GCC/GDB（实际 MinGW CRT；如有条件验证 Dev-C++ 附带工具链）。Linux LLDB 可作为补充。记录 OS、架构、编译器、调试器、CRT 版本、真实命令及原始输入编码；CI 交叉构建不等于实机验证。

每个平台以相同程序、输入和调试器配置进行开启/关闭探测的对照。记录每快照额外延迟、总耗时、成功率、位置是否精确、是否改变现有快照/输出/退出结果。重点关注默认 1000 快照/10 秒运行/2 秒单请求预算，避免每步多次昂贵请求。测试超时后能否正常停止和清理。先报告测量数据，不擅自扩大正式预算。

## 4. 建议的共享语义（仅供讨论，不直接实施）

若验证成功，再与前端协商向 Snapshot 增加可选输入位置字段，示意：

```json
{
  "input_position": {
    "status": "observed",
    "byte_offset": 5,
    "eof": false
  }
}
```

- byte_offset 是本次原始 stdin 字节串中的逻辑读取位置，0 <= offset <= len(stdin)；0 是有效位置，不是未知。eof 只有能可靠观测时才填写。不同于已有 OutputOffsets，输入可能回退。
- 缺字段表示旧记录或未启用；unsupported / unavailable / unmappable 等失败状态不填有效偏移。不能用 0、文件长度或最后一次位置冒充当前值。
- 若只获得不透明位置标记或近似值，保留在实验诊断，不进入精确回放字段。
- 输入内容只保存一次（现有运行配置/回放夹具提供），每步只保存位置和必要状态。前端比较相邻真实快照：本步新增消费范围、回退、无变化与未知应区分；无精确数据时退化为静态预览。行号由原始字节位置映射，不由后端猜测。
- 采集的含义是暂停点之间的可观测差异，不是完整 read 事件日志；同一步内读取后回退可能净变化为零，不应宣称从未读取。

## 5. 交付与验收

在独立短分支完成最小实验，优先使用现有真实调试器测试设施及 testdata/programs。实验开关默认关闭；不修改正式 UI、Companion、发布工作流、版本号或默认 stdin 行为。共享类型、正式接口及采集开关待双方确认后另行实施。不要为实验发布 npm 版本。

交付：
1. 可重复运行的夹具/命令、最小实验代码及测试结果。
2. 每个平台的逐暂停点记录：位置、读取返回值（由夹具提供或可靠观测）、探测结果、是否能映射原始字节、异常及耗时。附至少一份实际记录供前端分析；不得将人工构造记录称作真实。
3. 一份简短结论表：可靠支持 / 有限制 / 不支持；说明是否推荐进入正式实现，失败原因及维护成本。未实测平台明确标注。
4. 若建议进入正式实现，给出最小接口提案、降级策略与后续验收计划；若不可行，保留静态输入预览，勿伪造进度。

执行适用的 gofmt、go test ./...、go vet ./... 和真实调试器测试。不要因未能精确采集而把实验标为失败的开发交付；如实证明限制同样有价值。

本轮与变量身份修复、观察记录导入导出、TUI 布局及输出缓冲处理分离，不扩大范围。

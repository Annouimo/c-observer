# Codex 交接：变量身份修复与输出缓冲预研

基线 main（0.1.1）。遵守 AGENTS.md；后端由 Codex 负责，前端另行并行开发。此次输入消费位置预研已结束，接受 research/input-progress 的结论，保持静态输入，不引入输入探针。

## P0：真实 LLDB 身份回归

维护者导出了 macOS arm64 / cc / lldb-dap 的生日题真实记录（0.1.1，29 快照）。请向维护者获取原始 JSON（不将其本地路径、源码等未经审核直接提交公开仓库）。main 栈帧身份可靠，但所有变量身份均不可靠，且变量没有 declaration 字段。原始数值已记录：第 17→18 份快照（ID 16→17，较早暂停行 20）中 birthdays[2].date.day 从 1 到 3。现有 snapshot.go 仅从 raw.Extensions.Declaration 获取声明，identity.go 的 mark 要求声明文件/行与 Clang AST 匹配。因此整个变化链路失效。先核对原始 DAP 响应，而非假定 Apple adapter 不提供任何声明能力。记录包含完整冻结的装配源码（#line）和可见 main.c，可以用于复现。

1. 实测 Apple Xcode LLDB-DAP 的版本、变量响应、声明位置相关能力与可用只读接口，检查 #line、逻辑路径映射、声明文件/行、AST 解析是否成功。诊断需有界且不泄露环境。若提供标准 declarationLocationReference 等信息，评估对应 locations 请求与性能；不能假定版本支持。必要时调查低成本、基于明确证据的源码声明解析。不得单凭变量名、序号、临时引用、地址或栈深认定可靠身份。
2. 修复最外层 n、birthdays、q 的可靠身份及成员 ID；不误报未初始化存储为赋值。逐步扩大到 for 声明、循环体局部、函数参数和普通函数/递归帧。区分声明、动态生命周期、帧调用实例，防止循环重新进入、同名遮蔽、地址复用、跳过停靠导致错误合并。三个不同的 i 不得共享可靠 ID；对无法证明的情况维持 false。后端若不能判断初始化，记录限制，不把可读内存等同于已初始化值。
3. GDB 同样审查可靠身份覆盖。测试独立源码与 Companion 装配源码、循环作用域、同名变量、递归、调用返回、静态/全局、部分数组、不同作用域重新进入。验证原有执行对应语义（区间归因），不扩大到精确单行归因。
4. 同时核对字符串 ValueTruncated 语义（逻辑字符串值是否完整，与字符数组 ChildrenComplete 区分）；结构体 ChildrenComplete 为 false 可能仅因 adapter 缺少 NamedVariables 计数，不得不经验证改为 true。前端会独立支持完整字符串值比较，以及已观察预览重复项折叠。
5. 交付：最小修复、实际平台测试、明确未支持场景、真实新记录（至少生日题）及前后对照。重点验收 birthdays[2].date.day 1→3 可可靠比较；循环中的 index/x 等在初始化之后可可靠观察；不错误合并三个 i。不擅自改变共享接口；如需新增生命周期/初始化元数据，先提接口草案给双方确认。原始旧记录不得回填可信标记。

## P1：stdout 缓冲独立预研

生日题的 29 份快照中 stdout 偏移均为 0，最终输出只在 END 可见。当前输出重定向普通文件、快照记录已捕获的字节数。前端会按真实偏移显示增量，不预测 printf 时点。

比较现状、可控的行缓冲/无缓冲等低成本方案；明确是否需要运行目标函数、改变目标流类型或修改用户程序，评估 stdout/stderr 字节、返回值、errno、isatty/seek 行为、退出状态、停靠顺序及运行预算。考虑用户显式 setvbuf、fflush、无换行/逐字符输出、CRLF、UTF-8、异常退出、重定向及截断。PTY 不是透明替代，不强制启用。不要默认插桩、每步 fflush 或假定无副作用。实验开关默认关闭，报告实测平台和未验证平台。若无法满足只读定位，维持现有语义即可。先报告再决定正式实现，不发布版本。

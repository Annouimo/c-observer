# 数据优先回放：实施计划

长期规范见 [design.md](design.md)。本轮仅重构前端，不更换调试引擎、不修改 Companion、不发布版本。以现有 feat/tui 为基线，保留原有采集、重跑、历史、数据详情及输出对照能力。

## 实施顺序

1. 执行语义：ReplayStep 使用真实相邻快照，不减行号、不将变化归于后一个暂停点。首帧为观察起点，结束不是快照。现有引擎没有单行完成证据；区间变化必须明确标注，精确归因需与引擎侧协商契约和真实测试。
2. 主界面：少量执行上下文和变化摘要，全宽数据区；源码、输入输出、栈帧按需访问。保留既有导航、详情、历史和重跑入口。
3. 展示系统：为所有根对象保留最低可读空间，按宽高分配剩余预览空间；短值数组横排、长值索引列表、矩阵子表、嵌套分组。完整/紧凑/概览自动选择；范围、列宽、顺序在连续回放中保持稳定。
4. 详情与状态：保留真实下标及原值；明确未展示、未采集、无法读取和截断；支持详情回放及已记录范围浏览。
5. 验收：80×24、120×30、160×40 字符快照，覆盖多矩阵、18 位整数、嵌套数组、递归、稀疏下标、大量普通变量及原有夹具；真实 GDB/LLDB 回放与原生终端审核单列。

## 首批实现范围

新增前端 ReplayStep、区间提示、默认数据主视图、基础横向布局及公平预览高度分配。保留旧单区树状视图作为过渡入口。后续完善候选布局搜索、完整/紧凑/概览渲染、嵌套字段、固定范围及布局稳定性，并增加压力测试。不可将首批提交视为正式验收。

单行因果归因是正确性门槛；相邻快照差异不等于完整赋值日志，异步输出不按行归因。原始历史序号及暂停位置保留，筛选不改变比较基准。
